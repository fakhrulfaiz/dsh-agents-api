# Web browser for agents (2026-11-26)

Spec: `agentry-web/docs/superpowers/specs/2026-11-26-browser-automation-design.md`; plan: `agentry-web/docs/superpowers/plans/2026-11-26-browser-automation.md`.

## What changed

- New agent field `browser: boolean | null` (saved agents, inline session agents, session `agent` overlay). Anything else answers 400 `browser must be a boolean or null`. Absent or `null` uses the new config `browser.default` (default `false`).
- An agent with the browser on, in a chat on an Agentry Sandbox environment, gets Playwright MCP (`@playwright/mcp` 0.0.80, the version DSH pins) as the MCP server `browser`: tools `mcp__browser__browser_navigate`, `..._snapshot`, `..._click`, `..._type`, `..._take_screenshot` and the rest. The tool is built in memory on create and resume (`src/mount-browser.ts`) and never written to the session config; it is `required: false`, so a sandbox without the browser starts without the tools.
- It runs **inside the sandbox**. On the API host only the stdio bridge runs (`lib/sandbox-stdio-bridge.js`, source `src/sandbox/remote/stdio-bridge*.ts`): the MCP client starts it with `process.execPath`, and it starts `playwright-mcp --browser chromium --isolated --headless --output-dir <workspace>/.browser` in the sandbox as `agent` over an envd process stream (`EnvdProcessStream`) and relays stdin/stdout. Configuration reaches the bridge through its environment only (`AGENTRY_SANDBOX_URL`/`_KEY`, `AGENTRY_BRIDGE_OWNER`, `_SANDBOX_ID`, `_CWD`, `_USER`, `_COMMAND`, `_ENV`), so the service key is not on a command line and never enters the sandbox. Closing stdin stops the program after 2 s; SIGTERM/SIGINT stop it at once.
- There is no host browser. A local chat whose agent has the browser on gets no browser tools and a system prompt line saying the browser runs only in sandbox chats. A sandbox chat whose browser did not start gets a line pointing at the built-in **Web browser** template (a reset of the standard image does not add it). With the tools present, the section `agentry:browser` gives usage guidance (snapshots first, screenshots when the layout matters, no passwords or payment details unless the user gave them for that site, Stop does not undo clicks).
- Screenshots come back as tool images (`images` on `function_call_output`, see `2026-11-26-tool-images.md`).

## Sandbox image

Since 2026-11-27 the browser is in a separate image, `ghcr.io/fakhrulfaiz/agentry-sandbox-browser:1` (`agentry-sandbox/images/sandbox-browser/Dockerfile`, built from the slim standard image), with `@playwright/mcp` 0.0.80 and its Chromium in `/opt/ms-playwright`. envd processes do not get the image's `ENV`, so the bridge passes `PLAYWRIGHT_BROWSERS_PATH=/opt/ms-playwright`; Playwright's own state stays writable under `~agent/.cache/ms-playwright`. The API's built-in **Web browser** template (`tpl_builtin_web_browser`) points at that image, so a standard sandbox has no browser and needs a new chat on the browser template instead of a reset.

## Verified

- Spike against the dev Agentry Sandbox: MCP `initialize` and `tools/list` over the bridge (24 tools), `browser_navigate` to https://example.com, `browser_take_screenshot` returned a PNG image part, `ps` in the sandbox showed `chrome` processes; closing stdin ended the bridge with 0.
- Not yet: a live chat through the API (needs the API rebuilt, `pnpm build`, so `lib/sandbox-stdio-bridge.js` exists).
