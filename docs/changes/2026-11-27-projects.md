# Projects (2026-11-27)

Projects are named, owner-scoped groupings of chats. This note covers the first
API slice: the project CRUD routes and the delete guard. Session attachment,
project defaults on session create, and the `project_id` session list filter
are being added in the following tasks; the design is in the web repository at
`docs/superpowers/specs/2026-11-27-projects-sidebar-design.md`.

## Wire resource

```
{
  "id": "proj_…",
  "object": "project",
  "name": "Work",
  "status": "active",          // or "archived"
  "pinned": false,
  "agent_id": null,            // default agent for new chats here
  "environment": null,         // OAIEnvironmentConfig, null = default workspace
  "archived_at": null,         // epoch seconds once archived
  "created_at": 176...,        // epoch seconds
  "updated_at": 176...
}
```

Records live in Postgres (`projects`, migration `0005`) and are read and written
only through the authenticated owner. Foreign and unknown ids look the same:
get, update, archive, unarchive and delete answer 404 `resource_not_found`, and
list never returns another owner's projects.

## Routes

| Method | Path | Result |
| --- | --- | --- |
| POST | `/v1/agents/projects` | 201 `Project`; `name` is required and must not be empty after trimming |
| GET | `/v1/agents/projects` | 200 list page (`status=active\|archived\|all`, `limit`, `after`, `order`) |
| GET | `/v1/agents/projects/{project_id}` | 200 `Project` |
| POST | `/v1/agents/projects/{project_id}` | 200 `Project`; only `name`, `agent_id`, `environment` and `pinned` present in the body are changed |
| POST | `/v1/agents/projects/{project_id}/archive` | 200 `Project` with `status: "archived"` and `archived_at` set |
| POST | `/v1/agents/projects/{project_id}/unarchive` | 200 `Project` with `status: "active"` and `archived_at: null` |
| DELETE | `/v1/agents/projects/{project_id}` | 200 `{ id, object: "project.deleted", deleted: true }` |

`agent_id` is a saved agent id or null; `environment` is an environment config
or null. Both are defaults a client can preselect when starting a chat in the
project, not a copy of the agent or sandbox. Deleting a project never deletes
its environment: reusable sandboxes are managed separately.

## Delete refusal

A project with attached sessions cannot be deleted. The route counts the
caller's sessions referencing it before touching the store and answers 409
`project_has_sessions`. This is also required by the Postgres schema:
`sessions.project_id` has a foreign key to `projects(id)` without `ON DELETE SET
NULL`, so a hard delete would fail while sessions still point at the row and
leave a dangling reference if the constraint were removed. Archive the project
instead (its chats and history stay available under an archived section) or
move those chats out first.
